# 规则说明（U 系列）

规则分两类：**能数的**交给脚本，**判不了的**交给冷读者或人。
把两者混在一起，是最常见的失败来源——脚本硬判"懂没懂"，只会误伤。

| 编号 | 规则 | 谁判 | 级别 |
|---|---|---|---|
| U0 | 先定落地句：一句话，读完能复述 | 冷读者 | 闸门 |
| U1 | 单句不超过 25 字 | 脚本 | 硬 |
| U1b | 连续五句都不到 10 字，像电报 | 脚本 | 硬 |
| U2 | 术语与数据后面，跟一句人话翻译 | 脚本定位 + 人判 | 提示 |
| U2c | 自己加粗或引号标成术语的词，首次出现要解释 | 脚本 | 提示 |
| U3 | 抽象结论后面，跟具体场景或类比 | 脚本定位 + 人判 | 提示 |
| U4 | 三句连续推理之间，插一句着陆句 | 脚本 | 提示 |
| U5 | 紧身衣测试：删掉修饰语，语义不变则删 | 人 | 闸门 |
| U6 | 复述测试：最该记住的三句是否醒目 | 人 | 闸门 |
| U7 | 禁词：然而、值得注意的是、综上所述、赋能、抓手、本质上 | 脚本（加 --candidate） | 候选 |
| U8 | 每段不超过 3 句 | 脚本（加 --candidate） | 候选 |

## 豁免（防误伤）

- 列表、表格、代码块、引用块内的句子，不受 U1、U8 约束。
- 规范/笔记类文件加 `--norm`：U1 降为提示。
- 卡片刊头与标题不算正文，不参与句长判定。

## 字数口径

中文按字符计。英文与数字串按每两个字符折一个字。标点、URL、行内代码不计。

## 为什么句长不是最重要的一条

句长好数，所以好自动化。但它只是包装。
五十个短句堆在一起，读者照样读不懂。
所以脚本之外还有一层冷读者：另起一个没有上下文的会话，只给正文，问三句话——
读到什么、记住哪句、哪儿卡住。复述不出落点，就退回。

## 冷读者为什么要跑多次

实测过：同一份稿，两次判定结果相反。
单次判定有噪声，所以默认跑三次取多数。
